"Before I build anything, I draw the blueprint. Where does the nav go? Where's the main content? Where's the footer? Structure first. Code second."

Structure is the invisible skeleton that holds everything together. You can't see it when you look at a finished website, but remove it and everything falls apart. Every single webpage on the internet has a structure underneath it.

Think about a building. It has a foundation, walls, floors, a roof. Each part has a job. Each part is in the right place for a reason. A webpage is exactly the same — it has a header at the top, a main section in the middle, and a footer at the bottom. Those aren't design choices. They're structural ones.

Nova plans before she builds. That's not a personality trait — it's the best practice in web development. Developers call it information architecture: figuring out what goes where before you write a single line of code.

📚
Key Terms
Structure
The organized arrangement of parts that gives a webpage its layout and hierarchy. The skeleton everything else is built on.
Example: Header → Main Content → Footer is a basic webpage structure.
Semantic HTML
Using HTML tags that describe the meaning and purpose of content, not just how it looks. Semantic tags make structure clear to browsers, search engines, and other developers.
Example: Using <nav> for navigation instead of <div> — it tells everyone what that section is for.
Hierarchy
The order of importance and relationship between elements on a page. Some things are parents, some are children, some are siblings.
Example: A <nav> inside a <header> — the nav is a child of the header.
Blueprint
A plan or wireframe that shows what goes where before any code is written. Nova's first step on every project.
Example: Sketching boxes on paper labeled "header," "sidebar," "main," "footer" before opening a code editor.
🗺️
Explore · Nova's Blueprint

⬡ Webpage Blueprint
<header> — Top of page: logo, nav, title
The header lives at the top. It usually contains the logo, navigation links, and any top-level info. Users expect it here — don't surprise them.
<nav> — Navigation links
The nav holds your links — Home, About, Contact. Usually lives inside the header or at the top of the page. Screen readers look for this tag specifically.
<main> — The primary content of this page
The main section holds the primary content — the thing this page is actually about. There should only be one <main> per page. It's the star of the show.
<section> — A themed group of content
Sections group related content together. A page might have a hero section, a features section, and a testimonials section — each is a <section>.
<footer> — Bottom: links, copyright, contact
The footer lives at the bottom. It usually has copyright info, social links, secondary navigation, and contact details. Always expected at the bottom.

Building Blocks of a Webpage

Every webpage is assembled from components. Nova knows every block, what it does, and exactly where it belongs.

⬡
Sparks · Builders · Coders
This lesson is for members
Join the crew to unlock Lesson 2 and start assembling with Nova.

Read · 3 min

"Every component has a job. A nav navigates. A button triggers. A form collects. Use the right block for the right job and your page practically builds itself."

HTML has a tag for almost everything. Some tags hold other things — like containers. Some tags display content — like images and paragraphs. Some tags let users interact — like buttons and forms. Knowing which tag to reach for is the difference between a messy page and a clean one.

Nova thinks of HTML tags like building supplies. You wouldn't use a window where a wall goes. You wouldn't use a door where a floor goes. Each tag has a purpose — and using the right one makes your code easier to read, easier to style, and easier to fix later.

📚
Key Terms
<div>
A generic container with no semantic meaning. Used to group elements for styling or layout purposes when no semantic tag fits.
Example: Wrapping a card component in a div to style it as a unit.
<img>
Displays an image. Uses the src attribute for the image file and alt for a text description. One of the few self-closing tags — no closing tag needed.
Example: <img src="nova.png" alt="Nova the builder bot">
<button>
A clickable button that triggers an action. Used for forms, interactive features, and any UI element the user needs to click to do something.
Example: <button>Build It →</button>
<ul> and <li>
ul creates an unordered (bulleted) list. Each item inside is an li. Used for navigation menus, feature lists, and any set of related items.
Example: A navigation menu is almost always a ul with li items inside.
<form> and <input>
Forms collect data from users. Input creates a field where users can type. Together they power login pages, search bars, and contact forms.
Example: <form><input type="email" placeholder="your@email.com"></form>

Lesson 03 · Builders+

Layout & Nesting

Elements don't just sit next to each other — they live inside each other. Nesting is how structure becomes layout.

⬡
Builders · Coders
This lesson is for Builders and up
Upgrade to unlock Lesson 3 — where structure becomes a real layout.
📖
Read · 3 min

"Nesting is like Russian dolls. The header holds the nav. The nav holds the links. The links hold the text. Everything is inside something else — and that's what makes it a layout."

Nesting is when one HTML element lives inside another. The outer element is the parent. The inner element is the child. The child inherits properties from the parent — like position and some styles — and the parent controls the layout of its children.

This is the core of how webpages are structured. A header contains a logo and a nav. The nav contains links. The main section contains articles. Each article contains headings and paragraphs. Layer by layer, the page takes shape.

When you understand nesting, you understand why CSS works the way it does. Styles cascade from parent to child. Layout decisions at the parent level affect everything inside it. Structure determines everything.

📚
Key Terms
Nesting
Placing one HTML element inside another. The outer element is the parent, the inner is the child.
Example: A <nav> inside a <header> — nav is the child, header is the parent.
Parent / Child
Parent elements contain child elements. A child can only have one direct parent. A parent can have many children.
Example: <ul> is the parent of every <li> inside it.
Indentation
Moving code inward with spaces or tabs to show that it's nested inside something else. Indentation is how developers read structure at a glance.
Example: Child elements are indented two spaces from their parent.
Container
An element that exists primarily to hold and organize other elements — like a box that groups things together for layout purposes.
Example: A <div class="card"> that wraps an image, a title, and a button together.

📚
Key Terms
Wireframe
A simple sketch or diagram showing the layout and structure of a page before any design or code. Every professional project starts here.
Component
A reusable piece of UI — like a card, a button, or a nav bar. Components are built once and used many times, like Loop's loops.
Example: A product card with an image, title, price, and button is a component.
Responsive
A webpage that looks good on all screen sizes — phone, tablet, desktop. Built using flexible layouts and CSS rules that adapt to screen width.
Deploy
Putting your webpage live on the internet so anyone can visit it. GitHub Pages is one way to deploy — it's how this entire platform works.
