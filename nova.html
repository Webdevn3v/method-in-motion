Read · 3 min What Builders Do First

"I never open a code editor first. I grab a piece of paper and I draw boxes. Header here. Navigation here. Main content here. Footer here. Blueprint first. Code second. Every time."

Structure is the invisible skeleton underneath every website you have ever visited. You can't see it when a site is finished and polished — but pull it away and everything collapses. Before a single line of code gets written, real developers figure out what goes where. They call this information architecture.

Think about a building. Architects draw blueprints before construction crews show up. The blueprint answers: how many floors? Where are the doors? What goes on each level? A webpage is identical. The blueprint answers: what's at the top? What's the main content? What lives at the bottom? What sections does this page need?

The language we use to define that structure is called HTML — specifically, semantic HTML. Semantic means meaningful. Instead of labeling everything as a generic box, semantic HTML uses tags that describe what each part of the page actually is. A header tag means "this is the header." A nav tag means "this is navigation." A footer tag means "this is the footer." Browsers understand this. Search engines understand this. And other developers reading your code understand this immediately.

Nova's rule: before you build, you plan. Before you plan, you understand why structure matters. That's what this lesson is about.

Key Terms The Vocabulary of Structure
Structure
The organized arrangement of sections that gives a webpage its shape and hierarchy. The skeleton everything else is built on.
Example: Header → Main Content → Footer is the foundational structure of nearly every webpage on the internet.
Semantic HTML
Using HTML tags that describe the meaning and purpose of content, not just how it looks. Semantic tags tell browsers, search engines, and developers what each section is for.
Example: <nav> for navigation links, <main> for primary content, <footer> for the bottom section — each tag communicates purpose, not just position.
Hierarchy
The order of importance and relationship between elements on a page. Some things are more important than others. Some things live inside other things. Hierarchy is how that's communicated in code.
Example: A page title (h1) is more important than a section subtitle (h2) which is more important than a detail (h3). Hierarchy goes from most important to least.
Blueprint
A plan or wireframe showing what goes where before any code is written. Nova's non-negotiable first step on every single project.
Example: Sketching boxes on paper labeled "header," "hero section," "features," "testimonials," "footer" — before opening a code editor.
Information Architecture
The practice of organizing and labeling content on a webpage so users can find what they need and the page makes logical sense. Used by every professional web developer and UX designer.
Example: Deciding that the login button goes in the top-right corner because that's where every user expects it — that's an information architecture decision.

⬡ Nova's Webpage Blueprint — click any section
<header> — Top of page
The header sits at the very top. It holds your logo, site name, and primary navigation. Users expect it here — breaking this convention costs you trust immediately. Nova always locks this in first.
<nav> — Navigation links
Navigation lives inside the header. It holds your site's main links — Home, About, Projects, Contact. Screen readers specifically look for this tag to help users navigate. Using <nav> instead of <div> is the semantic choice.
<main> — Primary content
The main section holds everything this specific page is actually about. There should only ever be one <main> per page. It's the star. Everything else supports it. Search engines weight this section most heavily.
<section> — Themed content group
Sections divide the main content into meaningful chunks. A homepage might have a hero section, a features section, a testimonials section. Each is a distinct <section> with its own heading and purpose.
<article> — Standalone content
An article is content that could stand on its own — a blog post, a news story, a product listing. Unlike a section (which is part of the page), an article makes sense outside the page context too.
<footer> — Bottom of page
The footer closes the page. Copyright info, social media links, secondary navigation, contact details — all expected here. Nova never skips the footer. It's part of a complete, professional build.

Read · 3 min The Right Block for the Right Job

"Every component has a job. A nav navigates. A button triggers. A form collects. An image displays. Use the right block for the right job and your code practically explains itself."

HTML has a tag for almost everything you'd want to put on a webpage. Some tags hold other things — they're containers. Some tags display content — like images and text. Some tags let users interact — like buttons and forms. Knowing which tag to reach for is what separates clean, professional code from a messy pile of divs.

Nova thinks of HTML tags the way a builder thinks about materials. You wouldn't use drywall where you need a beam. You wouldn't put a window where a wall goes. Every material has a purpose. Every HTML tag has a purpose. Using the right one makes your page faster to build, easier to style, easier to fix — and easier for other developers to read later.

This lesson is your component library. By the end, you'll know exactly which tag to reach for any situation Nova throws at you.

Key Terms Your Component Library
<div> — The Generic Container
A container with no semantic meaning — use it when no other tag fits the job. Good for grouping elements that need to be styled or positioned together.
Example: <div class="card"> wrapping an image, title, and button together into one styled unit.
<img> — Images
Displays an image. Uses the src attribute for the file path and the alt attribute for a text description (important for accessibility and SEO). Self-closing — no closing tag needed.
Example: <img src="nova-blueprint.png" alt="Nova's webpage blueprint">
<button> — Clickable Actions
A clickable element that triggers something — submitting a form, opening a menu, running JavaScript. Always use a button for actions, never a div or a link.
Example: <button onclick="buildIt()">Build It →</button>
<ul> and <li> — Lists
ul creates an unordered (bulleted) list. Each item inside is an li. Navigation menus are almost always a ul with li items — this is the standard pattern used by every professional developer.
Example: A nav menu: <ul><li>Home</li><li>About</li><li>Contact</li></ul>
<form>, <input>, <label> — User Input
Forms collect data from users. Input creates a field to type into. Label ties a text description to an input (critical for accessibility). Together they power login pages, search bars, contact forms, and sign-up flows.
Example: <label for="email">Email</label><input type="email" id="email" placeholder="you@email.com">
<span> — Inline Wrapper
A generic inline container — like a div but for text-level content. Used to style or target a specific word or phrase within a sentence without breaking the flow of text.
Example: <p>Nova's color is <span style="color:#ffe066">yellow</span>.</p>

Read · 3 min Layers on Layers

"Nesting is like Russian dolls. The header holds the nav. The nav holds the ul. The ul holds the li items. The li items hold the links. Every layer is inside the last. That's how a page is built."

Nesting is when one HTML element lives inside another. The outer element is called the parent. The inner element is called the child. A child inherits certain properties from its parent — like position, some CSS styles, and visibility. A parent controls the layout of everything inside it.

This is fundamental. A header doesn't just contain a nav — the header IS the parent of the nav. The nav IS the parent of the ul. The ul IS the parent of every li. Layer by layer, the page takes shape. When you understand this hierarchy, you understand why CSS works the way it does, why JavaScript can find elements so efficiently, and why good indentation in your code isn't just cosmetic — it's how you communicate structure to everyone who reads your code.

Nova says: indentation is documentation. Every time you indent a child element under its parent, you're drawing the blueprint in your code. Don't skip it. Don't compress it. Your future self will thank you.

Key Terms The Language of Nesting
Nesting
Placing one HTML element inside another to create a hierarchical relationship. The outer element is the parent. The inner is the child.
Example: <nav><ul><li>Home</li></ul></nav> — nav is parent of ul, ul is parent of li.
Parent / Child / Sibling
Parent: the outer element that contains others. Child: the inner element. Sibling: two elements that share the same parent. Understanding these relationships is how you read and write CSS selectors.
Example: Two <li> elements inside the same <ul> are siblings. The <ul> is their parent.
Indentation
Moving code inward with spaces or tabs to visually show nesting depth. Standard is 2 spaces per level. Indentation is how developers read structure in seconds — and how Nova knows her blueprints are clean.
Example: A child element always sits 2 spaces to the right of its parent's opening tag.
Cascade (CSS)
Styles flow from parent to child automatically. Set a font on the body and every child inherits it unless you override it. This is why nesting and CSS are inseparable — the DOM structure determines how styles apply.
Example: body { color: white; } makes ALL text on the page white unless a child element overrides it.
DOM (Document Object Model)
The tree structure a browser builds from your HTML. Every element is a node. Parent-child-sibling relationships in HTML become parent-child-sibling nodes in the DOM. JavaScript navigates the DOM to find and change elements.
Example: When JavaScript uses document.querySelector('nav a'), it's navigating the DOM tree to find all anchor tags inside any nav element.

  • Clean nesting = readable code = faster debugging = professional output

Read · 2 min The Moment Everything Connects

"The first page I ever deployed was about my favorite video game. Three sections. A header. A footer. It was simple. But when I opened that file in my browser and saw it — MY page, that I built — nothing felt the same after that."

Every real webpage on the internet starts as a single HTML file. Inside that file is a skeleton — a <head> section that holds settings the browser needs, and a <body> section that holds everything a visitor actually sees. That's the complete document structure. Every site. Every app. Every page you've ever visited. This is what's underneath.

In this lesson you're going to fill in that skeleton with your own content. You'll pick your topic, write your heading, build your sections, style your colors. The builder on the right previews your page live as you type. When you're done, you'll download a working .html file — something you can open in any browser on any computer. That file is yours.

Nova's final rule: ship something. Imperfect and real beats perfect and imaginary every single time.

Key Terms The Complete Document
<!DOCTYPE html>
The very first line of every HTML file. Tells the browser this is an HTML5 document. Non-negotiable — always first, always present.
<head>
The invisible settings section. Holds the page title (what shows in the browser tab), links to CSS files, meta tags for SEO, and more. Not visible on the page itself.
Example: <title>Nova's Portfolio</title> — this text shows in the browser tab, not on the page.
<body>
Everything the visitor actually sees goes here. Every heading, paragraph, image, button, section, nav, footer — all of it lives inside <body>.
<style>
A tag inside <head> that lets you write CSS directly in the HTML file. For small pages and learning projects, this is the fastest way to add styles.
Example: <style>h1 { color: #ffe066; font-size: 2rem; }</style>
