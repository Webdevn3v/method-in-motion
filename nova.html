Lesson 1

Blueprint Thinking

"Before a builder picks up a single tool, they study the blueprint. HTML is the blueprint of everything on the web."

Every website you have ever visited — social media, games, stores, school portals — was built on the same foundation: HTML. It is not magic. It is structure. And once you learn to read it, you will never look at a webpage the same way again.

The Three Layers of Every Website

  • HTML — Structure. The walls, floor, and ceiling of your digital room.
  • CSS — Style. The paint color, lighting, and furniture.
  • JavaScript — Behavior. The lights that switch on, the door that opens when you knock.

Nova's world covers HTML completely. You will learn to describe what is on a page, where it lives, and how everything connects. CSS and JavaScript come later with other characters. But nothing works without the structure Nova is about to teach you.

How the Browser Reads Your Code

When you open a website, your browser downloads a file and reads it top to bottom, exactly like reading a book. Every tag you write is an instruction. The browser follows every instruction in order. This predictability is your power as a builder. You are always in control of what appears and where.

Your First HTML File
<!DOCTYPE html>
<html>
  <head>
    <title>My First Page</title>
  </head>
  <body>
    <h1>Hello, World!</h1>
    <p>I built this myself.</p>
  </body>
</html>

This is a complete, working HTML page. Five minutes from now you will understand every single line of it.

Terminology

Lock these in. Every builder needs this vocabulary to read, write, and talk about HTML.

HTML
HyperText Markup Language. The language used to structure every webpage on the internet.
Element
A single HTML component. A heading, paragraph, image, or link. Everything on a page is an element.
Tag
The code that marks where an element starts and ends. Opening: <h1>. Closing: </h1>.
Browser
Chrome, Safari, Firefox. The program that reads your HTML and turns it into the visual page a visitor sees.
<head>
The invisible section. Holds your page title and setup code the browser uses but visitors never see.
<body>
Everything inside <body> is what your visitors actually see and interact with.
Structure
The organization of a page. Which things come first, how they are grouped, and how they relate to each other.
Markup
The act of wrapping content in tags to give it meaning. "Marking up" text as a heading tells the browser it is important.

Theory

Why Does Structure Come First?

Imagine building a house by painting the walls before laying the foundation. That is what happens when people try to learn CSS or JavaScript before HTML. Everything breaks. Structure is the only safe starting point because everything else depends on it.

The Document Object Model (DOM)

When your browser reads HTML, it builds a tree called the DOM — Document Object Model. Every element becomes a branch of that tree. The title is a branch. The heading is a branch. The paragraph is a branch. This tree is how browsers understand your page and how JavaScript can later reach in and change things live without reloading.

HTML Describes What, Not How

HTML describes what something is, not how it looks. A <h1> tag does not make text large because it is stylish. The browser applies default visual treatment to help users understand hierarchy. Design lives in CSS. Keep these two jobs completely separate in your mind from day one. Mixing them up is the most common beginner mistake.

Every Site You Have Used Was Built This Way

YouTube, Instagram, your school portal, online games — all of them start as HTML files. Professional developers are reading and writing the same tags you are about to learn. The only difference is practice and scale. You are not learning a simplified version of web development. You are learning the real thing.

Blueprint Hunt — Offline Activity

Before you can build on the web, train your brain to see structure everywhere. This offline activity takes 15-20 minutes and builds the same mental skill HTML requires.

  1. Find a physical magazine, newspaper, or printed flyer near you.
  2. Grab a pencil or pen and draw boxes around each section you can identify — headlines, images, body text, captions, footers.

  5. On a separate piece of paper, write out what the HTML skeleton of one page might look like using the tags from your Terminology section.

Lesson 2

Building Blocks

"Every structure is made of components. Learn each block individually. Then combine them into something real."

HTML gives you a toolbox. Each tool does exactly one job. A heading creates hierarchy. A paragraph holds text. An image embeds a visual. A link connects pages. A list organizes items. Learn each block, and you can build anything.

Text: Headings and Paragraphs

Headings run from <h1> to <h6>. h1 is the most important — use it once per page for the main title. h2 through h6 create sub-levels of organization, like chapters and sub-chapters in a book. The browser applies different sizes by default, but remember: semantic meaning, not visual size, is the real purpose.

Headings and Paragraphs
<h1>Page Title</h1>
<h2>Section Title</h2>
<h3>Sub-section</h3>
<p>A paragraph of body text goes here.</p>

Images

The <img> tag is self-closing — no closing tag needed. It uses two key attributes: src tells the browser where to find the image file, and alt provides a text description for screen readers and when the image fails to load.

Image Tag
<img src="nova.png" alt="Nova the Builder Bot">

Links

The <a> (anchor) tag creates links. The href attribute is where clicking takes the user. You can wrap text or images inside an anchor to make them clickable.

Link Tag
<a href="https://methodinmotion.org">Go to MiM</a>

Lists

<ul> creates a bullet list. <ol> creates a numbered list. Each item inside uses <li>. Lists are used for navigation menus, feature lists, step-by-step instructions — almost everything that comes in a group.

Terminology

<h1> to <h6>
Heading tags. h1 is the main title. Each number down is a smaller sub-heading. Use them in order — never skip levels.
<p>
Paragraph tag. Every block of body text lives inside a <p>. Never leave text floating without a tag.
<img>
Image tag. Self-closing. Needs src= to find the image and alt= to describe it.
<a>
Anchor tag. Creates a clickable link. The href= attribute sets where it goes.
src=
Source attribute. Used in <img> to point to the image file location.
href=
HyperReference attribute. Used in <a> to set the link destination.
alt=
Alternative text. Describes an image for screen readers and when the image cannot load. Required.
<ul> / <ol> / <li>
Unordered list (bullets), ordered list (numbers), and list item. Always nest <li> inside <ul> or <ol>.
Attribute
Extra information added inside a tag. Written as name="value". Customizes what the element does.
Self-closing Tag
A tag that does not need a closing partner. <img> and <br> are self-closing because they contain no text content.

Theory

Paired Tags vs Self-Closing Tags

Most tags wrap content: there is an opening tag, the content, and a closing tag. But some elements do not wrap content — they are standalone instructions. <img> places an image. <br> breaks a line. There is nothing to wrap, so there is no closing tag. Understanding which tags are paired and which are self-closing prevents common syntax errors.

Attributes Give Tags Instructions

A tag describes the type of element. Attributes give that element specific instructions. An <a> tag means "this is a link." Adding href="https://..." tells the browser where the link goes. Without the attribute, the tag exists but does nothing useful. Think of the tag as the noun and the attribute as the verb.

Alt Text Is Not Optional

Many beginners skip alt text because the page looks the same without it. But alt text is read aloud by screen readers used by people with visual impairments. It also appears when an image fails to load. A page without alt text excludes users and breaks accessibility standards. Professional developers are required to include it. So should you.

Semantic Heading Order

Skipping heading levels — going from h1 directly to h4 — breaks the document's semantic structure. Search engines use heading hierarchy to understand your content. Screen readers use it to navigate. Use headings to create a real outline: one h1, multiple h2s for main sections, h3s inside those sections. It is like writing a proper outline before an essay.

Layout & Nesting

"Individual bricks do not make a building. You need to group them, stack them, and organize them. That is what layout is."

You know the individual building blocks. Now it is time to put them together. Real webpages are not just a list of elements stacked one after another. They are groups of elements organized into sections — and sections nested inside containers. This is how layout works.

The <div> Tag

A <div> is a generic container. It has no visual appearance on its own — it is purely structural. You use it to group related elements together so you can position and style them as a single unit with CSS later.

Grouping with Divs
<div class="card">
  <h2>Nova</h2>
  <p>Builder Bot</p>
  <a href="nova.html">Enter World</a>
</div>

Semantic Tags

HTML5 introduced tags that describe their purpose: <header>, <nav>, <main>, <section>, <article>, and <footer>. Use these instead of plain divs wherever they fit. They make your code readable, help search engines, and support accessibility tools.

Semantic Page Structure
<header>
  <nav><a href="/">Home</a></nav>
</header>
<main>
  <section>
    <h1>Welcome</h1>
    <p>Page content here.</p>
  </section>
</main>
<footer>Built with MiM</footer>

Terminology

<div>
Generic container. Groups elements so they can be styled and positioned together. No visual style by default.
Nesting
Placing elements inside other elements. The inner element is the child. The outer is the parent.
<header>
Top section of a page or component. Usually holds the logo, navigation, and page title.
<nav>
Navigation container. Holds links that help users move around the site. Tells screen readers this is a menu.
<main>
The primary content of the page. There should only be one <main> per page.
<section>
A thematic group of content. Use for major page areas like "About," "Projects," or "Contact."
<footer>
Bottom of a page. Holds copyright info, extra links, and contact details.
class=
Attribute that gives an element a reusable label. CSS and JavaScript use class names to target elements.
Parent / Child
An element that contains another is the parent. The element inside is the child. CSS styles can cascade from parent to child.
The Box Model
Every HTML element is a box with content, padding (inside space), border, and margin (outside space).

Theory

Why Semantic HTML Matters

A screen reader cannot guess that your <div class="header"> is a page header. But <header> communicates its role instantly — to the browser, to accessibility tools, and to search engines. Semantic HTML makes your page smarter without any extra effort. It is the same information with the same visual result, but far more meaningful to the systems that process it.

Nesting Rules — Never Break These

Children must close before their parent closes. If you open a <div>, then open an <h2> inside it, you must close the <h2> before you close the <div>. Breaking nesting rules causes invisible bugs that are incredibly hard to track down. Use indentation — tabbing child elements to the right — to keep your nesting visible and valid.

The Box Model Is Everything in CSS

Every HTML element is a box. That box has four layers: the content itself, padding (space between content and border), the border, and margin (space outside the border). Understanding this is the foundation of all CSS layout. When you move to CSS, you will control every one of these layers precisely. Get comfortable thinking of elements as boxes now.

Divs vs Semantic Tags

A common beginner mistake is using <div> for everything. A better practice: use semantic tags when the purpose is clear (header, nav, main, footer, section), and use <div> when you just need a generic grouping container for styling with CSS. The more semantic your HTML, the more professional and maintainable your code.
