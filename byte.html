Bug Thinking
LESSON 01 · FREE
01 / 04

Bugs Are Normal

A bug is anything that makes your code do something different from what you intended. Every programmer, from beginners to senior engineers, writes bugs. The skill isn't avoiding them — it's finding and fixing them fast.

02 / 04

Where the Word Comes From

The name comes from 1947, when a real moth got stuck inside a computer and caused it to malfunction. Grace Hopper's team literally debugged a machine — and taped the moth into their logbook.

03 / 04

Three Types of Bugs

Syntax errors — the code is written wrong, like a typo. Logic errors — the code runs but gives the wrong result. Runtime errors — the code crashes while it's running.

04 / 04

Byte's Method

Read the error message. Reproduce the bug. Isolate where it happens. Fix one thing at a time. Test after each change. Never guess randomly.

Error Messages
LESSON 02 · SPARKS+
01 / 04

An Error Is a Gift

"An error message is not your enemy. It's Byte's gift to you." Every error has three parts: the type, the message, and the location (file and line number).

02 / 04

ReferenceError

You tried to use a variable that doesn't exist. Usually a typo in the variable name, or using it before it's defined.

03 / 04

TypeError

You tried to do something with a value that doesn't support that action — like calling .length on a number.

04 / 04

The Line Number Is a Hint, Not the Answer

The error points to where JavaScript noticed the problem. The actual cause is often one or two lines earlier. Read around the line number, not just on it.

Key Terms
LESSON 02 · TAP TO EXPAND
ReferenceError ›
Using a variable that doesn't exist or wasn't defined yet.
TypeError ›
Performing an operation on a value that doesn't support it.
SyntaxError ›
Code written incorrectly — JavaScript can't parse it at all.
Stack Trace ›
The list of function calls that led to the error.

Logic Tracing
LESSON 03 · BUILDERS+
01 / 04

Become the Computer

"The bug is never where you think it is. You have to follow the code like a trail." Logic tracing means reading your code exactly as the computer would, tracking each variable's value as it changes.

02 / 04

console.log() Is Your Tracer

Place console.log() after key steps to print what a variable holds. If the value is unexpected, you've found your bug's neighborhood.

03 / 04

Trace Tables

A trace table tracks each variable's value at each step — columns for variables, rows for each line. Fill it in like a spreadsheet.

04 / 04

Off-By-One Errors

One of the most common logic bugs. Your loop runs one time too many or too few. Usually caused by < vs <=, or starting at 0 instead of 1.

Key Terms
LESSON 03 · TAP TO EXPAND
Logic Tracing ›
Reading code step by step, tracking variable values exactly as the computer would.
Trace Table ›
A chart tracking each variable's value at each step of execution.
Off-By-One Error ›
A loop runs one iteration too many or too few.
State ›
The current value of all variables at a specific moment during execution.

Byte's Debug Checklist

Read the error first. Identify the type. Go to the line number. Look around it. Add console.log() to check values. Fix one bug at a time. Test after each fix.

One Fix at a Time

Fixing multiple things at once makes it impossible to know what worked. Always fix one bug, test, then move to the next.
