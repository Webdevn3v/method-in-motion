Bug Thinking

"Most people panic when they see an error. I get excited. Every bug is just a clue waiting to be followed."

A bug is anything that makes your code do something different from what you intended. The name comes from 1947, when a real moth got stuck inside a computer and caused it to malfunction. Grace Hopper's team literally debugged a machine.

01

Bugs Are Normal

Every programmer, from beginners to senior engineers at major tech companies, writes bugs. The skill is not avoiding them. The skill is finding and fixing them fast.

02

Three Types of Bugs

Syntax errors — the code is written wrong, like a typo. Logic errors — the code runs but gives the wrong result. Runtime errors — the code crashes while it is running.

03

Byte's Method

Read the error message. Reproduce the bug. Isolate where it happens. Fix one thing at a time. Test after each change. Never guess randomly.

04

Console is Your Best Friend

The browser console shows you exactly what went wrong and where. Opening it is the first thing Byte does when anything breaks.

Three types of bugs in action
// SYNTAX ERROR — typo, missing bracket
consol.log("hello")  // "consol" should be "console"

// LOGIC ERROR — runs but gives wrong answer
let total = 5 + 3 * 2  // gives 11, not 16

// RUNTIME ERROR — crashes during execution
let name = null
console.log(name.length) // can't read .length of null

Key Terms

Bug
Any error that causes code to behave differently from what was intended.
Debugging
The process of finding, understanding, and fixing bugs in code.
Syntax Error
A typo or grammatical mistake in the code. The computer cannot even read it.
Logic Error
The code runs without crashing but produces the wrong result.
Runtime Error
The code looks fine but crashes when it actually runs.
Console
The browser's built-in tool that shows error messages and logged values.
Reproduce
Make the bug happen again on purpose so you can study it.
Isolate
Narrow down exactly which line or section of code is causing the problem.

Error Messages

"An error message is not your enemy. It is Byte's gift to you. It tells you exactly what went wrong and exactly where."
01

Anatomy of an Error

Every error message has three parts: the type (what kind of error), the message (what went wrong), and the location (which file and line number).

02

ReferenceError

You tried to use a variable that does not exist. Usually caused by a typo in the variable name or using something before it is defined.

03

TypeError

You tried to do something with a value that does not support that action. Like calling .length on a number, or calling a function on something that is not a function.

04

SyntaxError

The code is written incorrectly. JavaScript cannot even parse it. Missing brackets, wrong spelling of keywords, unclosed strings.

05

The Line Number is a Hint, Not the Answer

The error points to where JavaScript noticed the problem. The actual cause is often one or two lines earlier. Read around the line number, not just on it.

Reading a real error message
// This code produces a ReferenceError
console.log(userName)

// Error in console:
// ReferenceError: userName is not defined
//   at script.js:2

// What it tells us:
// Type: ReferenceError
// Message: userName is not defined
// Location: line 2 of script.js
// Fix: define userName before using it

Key Terms

ReferenceError
Using a variable that does not exist or was not yet defined.
TypeError
Performing an operation on a value that does not support it.
SyntaxError
Code written incorrectly. JavaScript cannot parse it at all.
Stack Trace
The list of function calls that led to the error. Helps you trace back where things went wrong.
Line Number
Where the error was detected. The real cause may be slightly earlier in the code.
console.log()
Prints values to the console so you can check what a variable holds at any point.

Logic Tracing

"The bug is never where you think it is. You have to follow the code like a trail. Step by step. Check every variable. Trust nothing."
01

What is Logic Tracing?

Logic tracing means reading your code exactly as the computer would, step by step, and tracking the value of each variable as it changes. You become the computer.

02

console.log() is Your Tracer

Place console.log() after key steps to print what a variable holds at that moment. If the value is unexpected, you found your bug's neighborhood.

03

Trace Tables

A trace table tracks each variable's value at each step. Draw columns for each variable, and rows for each line of code. Fill it in like a spreadsheet.

04

Off-By-One Errors

One of the most common logic bugs. Your loop runs one time too many or too few. Usually caused by using < instead of <= or starting at 0 instead of 1.

Trace this code step by step
let x = 5
let y = 3
let result = x + y   // result = 8
result = result * 2  // result = 16
result = result - x  // result = 11
console.log(result)  // prints: 11

// Trace table:
// Line | x | y | result
// 1    | 5 | - | -
// 2    | 5 | 3 | -
// 3    | 5 | 3 | 8
// 4    | 5 | 3 | 16
// 5    | 5 | 3 | 11

Key Terms

Logic Tracing
Reading code step by step, tracking variable values exactly as the computer would.
Trace Table
A chart tracking each variable's value at each step of execution.
Off-By-One Error
A loop runs one iteration too many or too few. Classic logic bug.
console.log()
Used as a tracer — print variable values at key points to see what the code actually holds.
Execution Order
The exact sequence in which code runs. Top to bottom, unless loops or functions redirect it.
State
The current value of all variables at a specific moment during execution.

Debug Challenge

"You have the tools. You know the types. You can trace the logic. Now prove it. Three bugs. One block of code. Find them all."
01

What You Will Use

Everything from Lessons 1-3. Recognizing bug types, reading error messages, and tracing logic step by step to find where values go wrong.

02

Byte's Debug Checklist

Read the error first. Identify the type. Go to the line number. Look around it. Add console.log() to check values. Fix one bug at a time. Test after each fix.

03

One Fix at a Time

Fixing multiple things at once makes it impossible to know what worked. Always fix one bug, test, then move to the next. This is how real engineers debug.
