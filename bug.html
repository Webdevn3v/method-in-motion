What Is a Bug?
LESSON 01 · FREE
01 / 05

Bugs Are Normal

Every programmer — from beginners to professionals — writes code with bugs. A bug is anything in your code that makes it behave differently than you intended. The goal is to find and fix bugs fast.

02 / 05

The Word "Bug" Is 80 Years Old

In 1947, engineer Grace Hopper found an actual moth stuck in a computer relay, causing it to malfunction. The word stuck. Today, bugs are everywhere — but they're always solvable.

03 / 05

Three Types of Bugs

Syntax errors — the code is written incorrectly. Runtime errors — the code starts running but crashes midway. Logic errors — the code runs fine but produces the wrong result.

04 / 05

Debugging Is a Skill

Debugging is a systematic process: understand what should happen, observe what actually happens, form a hypothesis, test it, fix it, verify.

05 / 05

The Console Is Your Best Friend

console.log() is the most basic debugging tool. When in doubt, log it out.

let total = 0; for (let i = 0; i < 5; i++) {   total += i;   console.log("i =", i, "total =", total); }
Key Terms
LESSON 01 · TAP TO EXPAND
Bug ›

Debugging ›

Syntax error ›
A mistake in how the code is written. The code can't run at all until it's fixed.
Runtime error ›
An error that happens while the code is running.
Logic error ›
The code runs without crashing but produces the wrong result.
console.log() ›
Prints a value to the browser console — the most basic debugging tool.

Reading Errors
LESSON 02 · SPARKS+
01 / 05

Error Messages Are Information

An error message is the computer telling you exactly what went wrong. The message is not an attack — it's a clue.

02 / 05

Anatomy of an Error Message

Most JavaScript errors have three parts: the error type, the message, and the location.

ReferenceError: x is not defined   at myFunction (script.js:12)
03 / 05

Common Error Types

ReferenceError — a variable that hasn't been declared. TypeError — the wrong type of value. SyntaxError — invalid code structure. RangeError — a value outside its allowed range.

04 / 05

The Call Stack

A call stack is a list of functions that were running when the error occurred. Read it top to bottom.

05 / 05

The Browser DevTools Console

Press F12 or right-click and choose Inspect, then click the Console tab. Open it every time you build something.

Logic Tracing
LESSON 03 · BUILDERS+
01 / 05

What Is Logic Tracing?

Logic tracing is running code in your head — step by step. You track every variable, every condition, every loop iteration.

02 / 05

Tracing a Loop

Track the value of every variable at every iteration. Create a simple table — columns for each variable, rows for each step.

let x = 1; let result = 0; while (x <= 4) {   result += x;   x++; } // Final result: 10
03 / 05

Off-By-One Errors

The loop runs one time too many or too few. Usually caused by < vs <=.

04 / 05

Tracing Conditionals

When tracing an if/else chain, work through each condition with the actual values. Don't assume — evaluate.

05 / 05

Rubber Duck Debugging

Explaining your code out loud forces you to slow down and say exactly what each line does.

Key Terms
LESSON 03 · TAP TO EXPAND
Logic tracing ›

Explaining your code out loud to find the bug yourself.
Boundary condition ›
Edge cases at the start and end of a loop or condition.
Infinite loop ›
A loop where the exit condition is never met.

Debug Challenge
LESSON 04 · CODERS
01 / 04

Advanced Debugging Strategies

Divide and conquer: narrow the problem by commenting out half the code. Minimal reproduction: strip the code down to the smallest version that still shows the bug.

02 / 04

try / catch — Catching Errors Gracefully

A try/catch block lets you run risky code and handle any error without crashing the whole program.

try {   let result = riskyFunction(); } catch (err) {   console.log("Caught: " + err.message); }
03 / 04

Defensive Programming

Defensive programming means writing code that anticipates problems before they happen.

04 / 04

The Debug Mindset

The best debuggers don't assume. They verify. Every assumption is a potential bug.
