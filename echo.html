Events & Listeners

01 / 05

Code That Waits

Most of the code you've learned so far runs immediately. But real web pages do something different -- they wait. They wait for a click, a keystroke, a scroll. This kind of code is called event-driven, and it's how the web actually works.

02 / 05

What Is an Event?

An event is anything that happens in the browser -- a user clicking a button, moving the mouse, pressing a key, or a page finishing loading. The browser tracks all of these moments automatically. Your job is to tell it what to do when one occurs.

03 / 05

addEventListener

The method addEventListener connects an element to a function. When the event fires, the function runs. The function is called an event handler or callback -- a function that gets called later, not right now.

const btn = document.getElementById("myBtn"); btn.addEventListener("click", function() { console.log("Button was clicked!"); });
04 / 05

The Event Object

When an event fires, the browser passes an event object to your handler. It contains information about what happened -- which key was pressed, where the mouse was, which element triggered it.

btn.addEventListener("click", function(e) { console.log("Clicked at X: " + e.clientX); });
05 / 05

Common Event Types

The browser supports dozens of event types you'll use often:

"click" // user clicks an element "keydown" // user presses a key "input" // value in a text field changes "load" // page or resource finishes loading
Key Terms

Timers & Timing
LESSON 02 · SPARKS+
01 / 05

Time Is an Event Too

Not all events come from users. Some come from time itself. JavaScript can schedule code to run after a delay, or on a repeating interval.

02 / 05

setTimeout -- Run Once After a Delay

setTimeout runs a function one time, after a specified number of milliseconds.

setTimeout(function() { console.log("3 seconds later..."); }, 3000);
03 / 05

setInterval -- Run Repeatedly

setInterval runs a function over and over at a fixed interval until you stop it.

const timer = setInterval(myFn, 500);
04 / 05

clearInterval -- Stopping the Loop

Always save the return value of setInterval so you can pass it to clearInterval.

05 / 05

Milliseconds and the DJ's Grid

At 120 BPM, one beat lasts 500ms. Formula: 60000 / BPM.

The Web Audio API
LESSON 03 · BUILDERS+
01 / 05

Browsers Can Make Sound

The Web Audio API is a built-in browser tool for creating and controlling audio with JavaScript. No plugins needed.

02 / 05

AudioContext -- The Studio

Everything happens inside an AudioContext. Think of it as the mixing board.

const ctx = new AudioContext();
03 / 05

OscillatorNode -- Generating Tone

An OscillatorNode generates a pure tone. Frequency is measured in Hz -- 440 Hz is the note A4.

const osc = ctx.createOscillator(); osc.frequency.value = 440; osc.connect(ctx.destination); osc.start();
04 / 05

GainNode -- Controlling Volume

A GainNode controls the volume of a signal. 1 = full volume, 0 = silent.

05 / 05

The Audio Signal Chain

Signals flow through a chain of nodes -- source, processing, then destination.

Beat Machine
LESSON 04 · CODERS
01 / 04

What Is a Beat Machine?

A step sequencer divides time into equal steps -- usually 16 per bar -- and plays a sound at each active step.

02 / 04

The Data Behind the Grid

Each row is an array of booleans -- 16 values, each true (on) or false (off).

03 / 04

The Sequencer Loop

A setInterval advances a step counter, checking each row for that step.

04 / 04

Click Events Toggle the Grid

Each button's click event toggles its boolean from false to true or back.
