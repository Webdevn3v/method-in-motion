Events & Listeners
LESSON 01 · SPARKS
01 / 08

First: Think of a Doorbell

Nothing happens until someone presses it. Your finger pressing the button is the event. The bell ringing is the response. A light switch works the same way: flip the switch, then the light responds. Web pages listen for moments like clicks, key presses, typing, and loading.

02 / 08

Code That Waits

Most beginner code runs right away, like a wind-up toy. Event-driven code waits quietly until something happens. An event listener is the part that waits and notices the event.

03 / 08

What Is an Event?

An event is a moment the browser notices: a click, mouse move, key press, input change, or page load. The browser tracks these moments automatically. Your code decides how to respond.

04 / 08

A Callback Is a Note for Later

Imagine leaving a note that says, “When the doorbell rings, open the door.” That note is like a callback function: instructions saved now so they can run later when the event happens. The function that responds is also called an event handler.

05 / 08

addEventListener Connects the Signal

addEventListener connects an element, an event, and the callback that should run.

const btn = document.getElementById("myBtn");
btn.addEventListener("click", function() { console.log("Button was clicked!"); });

Breaking Down These Lines

const — creates a label that will keep pointing to the same button.
btn — our short name for the button.
document.getElementById("myBtn") — asks the page to find the element named myBtn.
. — reaches into something to use one of its abilities.
addEventListener — means “wait for something to happen.”
( ) — holds the information we give that ability.
"click" — the event we are waiting for; quotes mean it is text.
, — separates the event from the instructions.
function() { ... } — the callback: instructions saved for later.
{ } — wraps the function body, the code that runs.

06 / 08

The Event Object Is a Tiny Report

When something happens, the browser can hand your callback an event object: a little report about what happened. It can include the mouse position, pressed key, or element involved.

btn.addEventListener("click", function(e) { console.log("Clicked at X: " + e.clientX); });

Breaking Down This Line

btn — the button we are listening to.
"click" — the event to wait for.
function(e) — the callback; e is our short name for the event object.
e.clientX — reaches into that report and reads the horizontal mouse position.
+ — joins the label text and the number for the console message.

07 / 08

Common Event Types

Different signals have different names.

"click" // user clicks an element
"keydown" // user presses a key
"input" // text-field value changes
"load" // page or resource finishes loading

Breaking Down These Lines

Quotes wrap each event name because event names are text.
// starts a comment for humans; JavaScript ignores the rest of that comment line.
Each name tells the listener which exact signal to wait for.

08 / 08

Echo's Signal Rule

Something happens → the listener notices → the callback responds. Say the chain out loud before writing code. If you can name those three parts, you can read event-driven code.

Key Terms

Code that waits for a chosen event and responds when it happens.

The specific signal name, such as click, keydown, input, or load.

Timers & Timing
LESSON 02 · SPARKS
01 / 08

First: Think of a Kitchen Timer

You set a kitchen timer for ten minutes. It waits, rings once, and stops. JavaScript's setTimeout works like that: wait for a delay, then run something one time.

02 / 08

Now Think of a Daily Alarm

An alarm clock can ring again and again until you turn it off. setInterval repeats code on a schedule. clearInterval is the off switch.

03 / 08

Time Can Trigger Code

Not every signal comes from a person. A timer can trigger code too. JavaScript measures short delays in milliseconds (ms). One second equals 1000 milliseconds.

04 / 08

setTimeout — Run Once

setTimeout(function() { console.log("3 seconds later..."); }, 3000);

Breaking Down This Line

setTimeout — asks JavaScript to wait, then run once.
( ) — holds the callback and delay.
function() { ... } — the instructions to run later.
, — separates the instructions from the delay.
3000 — wait 3000 milliseconds, which is 3 seconds.

05 / 08

setInterval — Repeat

const timer = setInterval(myFn, 500);

Breaking Down This Line

const timer = — saves the interval's ID so we can stop it later.
setInterval — repeats instructions on a schedule.
myFn — the callback to run each time.
500 — wait 500 milliseconds between runs.

06 / 08

clearInterval — Turn It Off

clearInterval(timer);

Breaking Down This Line

clearInterval — means “stop a repeating timer.”
(timer) — tells JavaScript exactly which saved interval to stop.
The saved ID is why we used const timer = ... above.

07 / 08

BPM Turns Music Into Timing

BPM means beats per minute. There are 60,000 milliseconds in one minute, so 60000 / BPM gives milliseconds per beat. At 120 BPM: 60000 ÷ 120 = 500ms per beat.

const msPerBeat = 60000 / BPM;

Breaking Down This Line

const msPerBeat = — creates a label for the answer.
60000 — milliseconds in one minute.
/ — division.
BPM — how many beats fit in that minute.
The result is the length of one beat in milliseconds.

08 / 08

Echo's Timing Rule

Once = setTimeout. Repeat = setInterval. Stop repeating = clearInterval. When music enters the picture, BPM tells us how fast those timed steps should move.

Key Terms
LESSON 02 · SPARKS
setTimeout ›
A one-time timer: waits for a delay, then runs a callback once.
setInterval ›
A repeating timer that runs a callback again and again until stopped.
clearInterval ›
Stops a repeating interval using its saved ID.
Millisecond (ms) ›
One thousandth of a second. 1000ms = 1 second.
Delay ›
The amount of time JavaScript waits before a scheduled action.
Interval ID ›
The saved identifier returned by setInterval so clearInterval can stop the correct timer.
BPM ›
Beats Per Minute. Use 60000 / BPM to find milliseconds per beat.
Callback ›
The instructions a timer runs later or repeatedly.

The Web Audio API
LESSON 03 · SPARKS
01 / 08

First: Picture a Sound Studio

A studio has a whole mixing setup, instruments making sounds, volume knobs shaping them, and speakers where the sound comes out. Browser audio works the same way.

02 / 08

Web Audio API — The Toolbox

The Web Audio API is the browser's built-in toolbox for creating and controlling sound with JavaScript.

03 / 08

AudioContext — The Whole Studio

An AudioContext is like opening the whole sound studio or mixing board. Audio nodes live and connect inside it.

const ctx = new AudioContext();

Breaking Down This Line

const ctx = — creates the short label ctx for our studio.
new — asks JavaScript to create a fresh instance.
AudioContext — the browser's audio studio object.
( ) — calls it so the new studio is created.

04 / 08

OscillatorNode — One Instrument

An OscillatorNode is like one simple instrument that makes one electronic tone. Its frequency, measured in hertz (Hz), controls pitch. 440 Hz is the note A4.

const osc = ctx.createOscillator();
osc.frequency.value = 440;
osc.connect(ctx.destination);
osc.start();

Breaking Down These Lines

ctx.createOscillator() — asks the studio to create one tone-making instrument.
osc.frequency.value = 440 — sets its pitch to 440 Hz.
osc.connect(ctx.destination) — connects the instrument to the output, usually your speakers.
osc.start() — starts the tone.
. — reaches into an object to use a property or method.

05 / 08

GainNode — The Volume Knob

A GainNode is a volume knob. A gain value near 1 is louder; 0 is silent.

const gain = ctx.createGain();
gain.gain.value = 0.4;

Breaking Down These Lines

ctx.createGain() — creates a volume-control node.
gain.gain.value — reaches the number controlling loudness.
= 0.4 — assigns a quieter volume value.

06 / 08

The Signal Chain — Connect the Cables

Like studio cables, sound travels through a signal chain: source → processing → destination. A useful chain is oscillator → gain → speakers.

osc.connect(gain);
gain.connect(ctx.destination);

Breaking Down These Lines

osc.connect(gain) — sends the tone into the volume knob.
gain.connect(ctx.destination) — sends the adjusted sound to the final output.
The order matters because the signal flows through the chain in that order.

07 / 08

Node Means One Piece of the Studio

An audio node is one building block in the chain. Some nodes create sound, some change it, and the destination sends it out.

08 / 08

Echo's Audio Rule

Create → set values → connect → start. Picture the physical studio first, then translate each piece into an audio node.

Key Terms
LESSON 03 · SPARKS
Web Audio API ›
Browser tools for creating, connecting, and controlling audio with JavaScript.
AudioContext ›
The whole browser audio studio where audio nodes are created and connected.
Audio node ›
One building block in an audio signal chain.
OscillatorNode ›
A tone-making source, like one simple electronic instrument.
GainNode ›
A node that controls loudness, like a volume knob.
Frequency ›
How fast a sound wave repeats; it controls pitch.
Hertz (Hz) ›
The unit used to measure frequency. A4 is 440 Hz.
Signal chain ›
The path audio follows through connected nodes: source → processing → destination.
Destination ›
The final audio output, usually the device speakers or headphones.

Beat Machine
LESSON 04 · SPARKS
01 / 07

First: Picture a Music Box

Imagine a spinning music-box cylinder with little pins. When a pin sticks out, it plucks a note. If no pin sticks out at that spot, nothing plays. A step sequencer is the digital version: time moves through equal steps, and active steps trigger sounds.

02 / 07

The Grid Is the Set of Pins

Each square in the grid answers one tiny question: “Should this sound play on this step?” The answer is a boolean: true means the pin is out/on; false means it is in/off. The rows and steps together are the sequencer's grid data.

03 / 07

The Timer Moves the Cylinder

A repeating setInterval acts like the motor. Each tick advances to the next step. BPM, from Lesson 2, controls how quickly those ticks happen.

04 / 07

Step Wrap — Start Again After 16

After step 15, a 16-step sequencer must return to step 0 instead of wandering forever. The step wrap formula uses the remainder operator %.

step = (step + 1) % 16;

Breaking Down This Line

step = — saves the next step number.
(step + 1) — move forward one step; parentheses group that math first.
% 16 — keep only the remainder after dividing by 16.
That makes the values cycle 0 through 15, then wrap back to 0.

05 / 07

Clicks Toggle the Pins

A click event toggles a boolean: false becomes true, or true becomes false. Visually, the square changes. Underneath, the real change is in the grid data.

beatGrid[row][step] = !beatGrid[row][step];

Breaking Down This Line

beatGrid — the stored grid data.
[row][step] — points to one exact square.
= — assigns a new value.
! — means “not,” flipping true to false or false to true.
The click changes the data; the button's look reflects that data.

06 / 07

The Whole Machine Is a Signal Chain

Click event → boolean changes → timer reaches the step → active sound triggers → audio nodes create the sound. Lesson 4 combines events, timers, data, and Web Audio into one system.

07 / 07

Echo's Sequencer Rule

Choose the pins → move one step at a time → play what is active → wrap and repeat. If the grid feels abstract, picture that spinning music box again.

Key Terms
LESSON 04 · SPARKS
Step sequencer ›
A music system that divides time into equal steps and triggers sounds on active steps.
Grid data ›
The stored rows and steps that remember which sounds are on or off.
Boolean ›
A value that can only be true or false; here it means a step is on or off.
Toggle ›
Flip between two states, such as false ↔ true.
Step ›
One position in the repeating timeline of a sequencer.
Step wrap ›
Returning to step 0 after the final step so the sequence can repeat.
Remainder operator (%) ›
Returns the remainder after division; useful for wrapping a counter in a loop.
BPM ›
Beats Per Minute; controls sequencer speed. Cross-reference: Lesson 2.
setInterval ›
The repeating timer that advances the sequencer step by step.
