Events & Listeners
LESSON 01 · FREE
01 / 05

Code That Waits

Most of the code you've learned so far runs immediately. But real web pages do something different -- they wait. They wait for a click, a keystroke, a scroll. This kind of code is called event-driven, and it's how the web actually works.

02 / 05

What Is an Event?

An event is anything that happens in the browser -- a user clicking a button, moving the mouse, pressing a key, or a page finishing loading. The browser tracks all of these moments automatically. Your job is to tell it what to do when one occurs.

03 / 05

addEventListener

The method addEventListener connects an element to a function. When the event fires, the function runs. The function is called an event handler or callback -- a function that gets called later, not right now.

const btn = document.getElementById("myBtn"); btn.addEventListener("click", function() { console.log("Button was clicked!"); });
04 / 05

The Event Object

When an event fires, the browser passes an event object to your handler. It contains information about what happened -- which key was pressed, where the mouse was, which element triggered it. You access it by adding a parameter to your function.

btn.addEventListener("click", function(e) { console.log("Clicked at X: " + e.clientX); console.log("Clicked at Y: " + e.clientY); });
05 / 05

Common Event Types

The browser supports dozens of event types. These are the ones you'll use most often when building interactive pages:

"click" // user clicks an element "keydown" // user presses a key "keyup" // user releases a key "mouseover" // mouse enters an element "input" // value in a text field changes "submit" // a form is submitted "load" // page or resource finishes loading
Key Terms
LESSON 01 · TAP TO EXPAND
Event ›
Something that happens in the browser -- a click, keypress, scroll, or page load. The browser tracks these automatically.
Event listener ›
A piece of code that "listens" for a specific event on a specific element and runs a function when it detects it.
addEventListener ›
The method used to attach a listener to an element. Takes the event type as a string and a function to call.
Callback function ›
A function passed to another function to be called later. Event handlers are callbacks -- they run only when the event fires.
Event object ›
The object the browser passes to your handler when an event fires. Contains details about the event -- position, key pressed, target element, etc.
Event-driven ›
A style of programming where code waits for user actions or system events before running. This is how all interactive web pages work.

Timers & Timing
LESSON 02 · SPARKS+
01 / 05

Time Is an Event Too

Not all events come from users. Some come from time itself. JavaScript has built-in functions that let you schedule code to run after a delay, or on a repeating interval. This is how animations, countdowns, and beat machines work.

02 / 05

setTimeout -- Run Once After a Delay

setTimeout runs a function one time, after a specified number of milliseconds. 1000ms = 1 second. It's perfect for delayed effects, loading states, and timed messages.

setTimeout(function() { console.log("3 seconds later..."); }, 3000); // 3000ms = 3 seconds
03 / 05

setInterval -- Run Repeatedly

setInterval runs a function over and over at a fixed interval. It keeps going until you stop it. This is the foundation of beat machines, clocks, and game loops.

let count = 0; const timer = setInterval(function() { count++; console.log("Beat: " + count); }, 500); // runs every 500ms
04 / 05

clearInterval -- Stopping the Loop

A setInterval that runs forever is a bug. Use clearInterval to stop it. Always save the return value of setInterval to a variable -- that's the ID you need to clear it.

const timer = setInterval(myFn, 500); // Later, stop it: clearInterval(timer);
05 / 05

Milliseconds and the DJ's Grid

At 120 BPM (beats per minute), one beat lasts 500ms. At 90 BPM, one beat is ~667ms. Changing your interval time changes the tempo. This is exactly how digital audio workstations schedule sound -- a loop running on a timer.

// Formula: ms per beat = 60000 / BPM const bpm = 120; const msPerBeat = 60000 / bpm; // = 500ms
Key Terms
LESSON 02 · TAP TO EXPAND
setTimeout ›
Runs a function once, after a delay in milliseconds. setTimeout(fn, 1000) runs fn after 1 second.
setInterval ›
Runs a function repeatedly at a fixed time interval until stopped. Returns an ID you can use to cancel it.
clearInterval ›
Stops a setInterval from running. Takes the interval ID as its argument.
Milliseconds (ms) ›
1/1000th of a second. All timing functions in JavaScript use milliseconds. 1000ms = 1 second.
BPM ›
Beats Per Minute -- the tempo of music. Convert to ms with: 60000 / BPM. At 120 BPM, one beat = 500ms.
Interval ID ›
The value returned by setInterval. Store it in a variable so you can pass it to clearInterval when you need to stop.

The Web Audio API
LESSON 03 · BUILDERS+
01 / 05

Browsers Can Make Sound

The Web Audio API is a built-in browser tool for creating, processing, and controlling audio with JavaScript. No plugins. No downloads. Just code. It's the same technology behind browser-based DAWs, games, and visualizers.

02 / 05

AudioContext -- The Studio

Everything in Web Audio happens inside an AudioContext. Think of it as the mixing board. You create one AudioContext, and all your sound nodes connect through it.

const ctx = new AudioContext(); // ctx.currentTime gives you the current time in seconds // ctx.destination is the output (your speakers)
03 / 05

OscillatorNode -- Generating Tone

An OscillatorNode generates a pure tone at a set frequency. Frequency is measured in Hz -- 440 Hz is the note A4 (concert A). Connect it to the destination and start it to hear sound.

const osc = ctx.createOscillator(); osc.frequency.value = 440; // A4 osc.type = "sine"; // sine, square, sawtooth, triangle osc.connect(ctx.destination); osc.start(); osc.stop(ctx.currentTime + 0.3); // stop after 0.3s
04 / 05

GainNode -- Controlling Volume

A GainNode controls the volume of a signal. Connect your oscillator through a GainNode before it reaches the destination. Gain 1 = full volume, 0 = silent.

const gain = ctx.createGain(); gain.gain.value = 0.5; // 50% volume osc.connect(gain); gain.connect(ctx.destination);
05 / 05

The Audio Signal Chain

Web Audio works like real audio gear -- signals flow through a chain of nodes. Source nodes generate sound. Processing nodes shape it. The destination node outputs it. You connect them like wires.

// Signal chain: oscillator → gain → output osc.connect(gain); gain.connect(ctx.destination); // You can add effects nodes in between: // osc → filter → reverb → gain → output
Key Terms
LESSON 03 · TAP TO EXPAND
Web Audio API ›
A browser-built-in system for creating and controlling audio with JavaScript. No plugins needed.
AudioContext ›
The main object you create to use Web Audio. All audio nodes are created from it and connect through it.
OscillatorNode ›
Generates a pure tone at a set frequency. Types include sine, square, sawtooth, and triangle waves.
GainNode ›
Controls the volume (amplitude) of a signal. Value of 1 = full, 0 = silent.
Frequency (Hz) ›
How many times per second a sound wave oscillates. Higher Hz = higher pitch. A4 = 440 Hz.
Signal chain ›
The path audio travels through connected nodes -- from source, through processing, to output (destination).

Beat Machine
LESSON 04 · CODERS
01 / 04

What Is a Beat Machine?

A step sequencer (beat machine) divides time into equal steps -- usually 16 per bar -- and plays a sound at each step that is turned on. Every DAW on earth uses this concept. Now you're going to build one with JavaScript.

02 / 04

The Data Behind the Grid

Each row in the beat machine is an array of booleans -- 16 values, each either true (on) or false (off). When the sequencer reaches a step, it checks: is this step on? If yes, play a sound.

// 4 rows × 16 steps const grid = [ [true,false,false,false, ...], // kick [false,false,true,false, ...], // snare [true,true,true,true, ...], // hihat [false,true,false,true, ...], // clap ];
03 / 04

The Sequencer Loop

A setInterval advances a step counter on every tick. At each step, the sequencer loops through all rows and checks if that step is active. Events + Timers + Audio -- all three concepts working together.

let step = 0; setInterval(function() { for (let row = 0; row < grid.length; row++) { if (grid[row][step]) { playSound(row); // play that row's sound } } step = (step + 1) % 16; // wrap back to 0 }, msPerBeat / 4); // 16th notes
04 / 04

Click Events Toggle the Grid

Each button in the grid has a click event. Clicking a step toggles its boolean from false to true or back. The grid data drives the sound, and the visual reflects the data. That's the connection between events and audio.

btn.addEventListener("click", function() { grid[row][col] = !grid[row][col]; // flip it btn.classList.toggle("active"); });
